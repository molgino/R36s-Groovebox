# SYNTH CITY (R36S-Groovebox) – Projektkontext

Name **SYNTH CITY** (Repo `molgino/synth-city`, vorher R36s-Groovebox; interne Pfade/Binary/Dienst heißen weiter `groovebox`). Neo-Noir-/Synthwave-Optik (eigene Gestaltung, keine geschützten Film-Namen/Logos): Palette `C_*` + Neon-`TCOL`, Kopfzeilen-Linie Magenta→Cyan, Scanlines in `drawAll`, Splashscreen `drawSplash/runSplash` (Shot-Seite 40, `GB_SPLASH_T`, abschaltbar `GB_NOSPLASH`). Elektron-artige Groovebox (C++/SDL2, ALSA) für den Handheld **R36S** (RK3326, ArkOS 2.0, Kernel 4.4.189, glibc 2.30).
Sprache mit dem Nutzer: **Deutsch**. Anleitung für Nutzer: `README.md`.

## Aufbau
- `src/engine.*` Sequencer + 13 Engines (KICK SNARE HAT CLAP SYNTH FM SMPL TOM RIM SHKR WTBL CHOP GRAN – Enum-Werte nur hinten anfügen, Anzeige-Reihenfolge `MACHINE_ORDER`), Wavetables `buildWavetables`, Insert-FX, Delay/Reverb, Kompressor mit Sidechain; Mikrotiming `P_MTIM` (`pend`/`preDone`, negative Werte werden einen Step früher geplant)
- `src/params.h` alle Parameter. Speicherseiten je Spur (TRG SRC FLT AMP LFO1 INS SRC2 LFO2 LFO3 SEQ FLT2 ARP, je 8 = 96 Parameter; `LFO_BASE`, `LF_*`) und UI-Seiten `PG_*` (TRG SEQ ARP SRC SR2 FLT FL2 AMP LF1 LF2 LF3 INS | MIX FX CMP | PRJ SNG MST SET; Reiter scrollen bei Platzmangel); SET (=PG_SYS) ist eine Listen-Seite (`SetItem`, `drawSettings`), Mapping `PG_STORE`; FM = 4 OP/8 Algorithmen (`FM_MODS/FM_CARRIERS/FM_LAYOUT`); globale Skala `mst[MS_SCALE]`
- `src/main.cpp` UI (640x480): Kacheln (`tile`, Wert-Symbole `paramSymbol` nach Parametername), Engine-Symbole (`drawIcon`), Engine-Wähler, Grafiken je Engine (`graphKind`), Bedienung, Einstellungen, PC-Modus-Steuerung
- `src/web.cpp` + `src/webpage.cpp` Mini-Webserver (Port 80, sonst 8080): Upload-Seite für Samples/Projekte, Umwandlung im Browser; nach Upload `reloadSamples` (Bibliothek neu lesen, geänderte Pool-Dateien neu laden)
- `src/remote.cpp` Bildschirm-Spiegelung + Fernbedienung: Hauptschleife legt bei Zuschauer (`remoteWanted`) max. 30/s `remoteSnapshot(fbPix)` als RGB565 ab, `/api/screen?since=` liefert Differenz (Tokens skip/run/literal, siehe Kopf in remote.cpp), Seite `/screen` (WEB_SCREEN in webpage.cpp), `/api/input?b=&v=` → `remoteDown/remoteHit/remoteAxis` in `Input::poll`; nur mit fbPix (Groovebox-OS oder `GB_HEADLESS=1` zum Testen)
- `src/midi.cpp` ALSA-Seq + rawmidi + USB-Seriell + RTP-MIDI (Port 5004/5005); `src/dhcpd.cpp` Mini-DHCP (`groovebox --dhcpd usb0`)
- `arkos/` Ports-Skripte, `arkos/groovebox/pc-modus.sh` (USB-Gadget: RNDIS + DHCP + SSH), `dtb-otg/` gepatchte DTBs
- Filter 1: Typen `FT_*` in params.h (nur hinten anfügen; LP12 BP HP12 LP24 LADR HP24 NTCH PEAK CMB+ CMB- VOWL), DSP `Voice::filter1`, Koeffizienten in render(), Kurven `filt1Mag` (main.cpp, auch Symbol); v10-Migration + Presets ohne hdr[6]: SYNTH/WTBL LP12 → LP24
- Klang: Oszillator-Drift (`drift1/2`); Drums 808/909-artig (Snare 2 Töne + Pitch-Env, Hat Zusatz-HP `hatHp`, Clap Sägezahn-Bursts). Pegel mit einem Einzelschlag-Messprogramm prüfen (Spitze ~0.3–0.5)
- Projektformat v10 (v9 gleiches Layout, `PROJECT_VERSION`; `Project` in engine.h: 96 Parameter, 128 Steps, `speed` pro Spur, `song[64]`/`songLen`; Index 5 = MTIM, bis v6 RFAD; Seite 10 FLT2 = Base-Width-Filter `P_BASE/P_WDTH` + `P_KEYT/P_VELF`; Seite 11 ARP `P_AMOD..P_AACC`) mit Migration v1–v9 in `Engine::load` (`remapLegacy`, v5-Zweig) – bei Strukturänderungen Version erhöhen + migrieren
- Sequencer: 12 Ticks pro 16tel (`doTick`/`stepTrack`), Tempo-Faktor `SPEED_TPS`, Trig-Bedingungen `P_COND` (`condOk`, Durchläufe `loopCount` über `stepCnt`), FILL `eng.fill`; SEQ-Seite: Richtung `P_DIR`, Euklid `P_PULS/P_EROT`, Turing-Generator `P_DENS/P_CHNG/P_RANGE` (`tmReg`), LEN/SPD zeigen auf `Pattern.len/speed`
- Arpeggiator: `Engine::Arp ar[]` in trigger() (fromSeq, nicht bei Drums), Timer im render-Block wie Retrig, `playNote()`; Song: `songOn/songPos/songRep`, Wechsel am Pattern-Ende in doTick, Seite SNG (`drawSong/songInput`); Pattern-Mutation `mutatePattern()` mit Undo (SET)
- Trigless Locks: `Step.on` 0 leer / 1 Trig / 2 trigless; stepTrack schreibt die Locks von on==2 in `v[t].lk`/`ar[t].lk` (ohne Note/LEN/COND/PROB), gelten bis zum nächsten Trig; UI: `aPrevOn` (A antippen auf Trig mit Locks → 2, auf 2 → 1), Lock-Modus SELECT+A toggelt, B löscht (2 → 0); Raster zeichnet 2 als Umriss
- Kopieren: Trig `trigClip` (A halten + L1/R1, Zustand `aPrevOn`), Seite `pageClip[8]`/`pageClipStore` im Seitenmenü (X/Y, SRC/SR2 nur gleiche Engine, SEQ inkl. len/speed), Pattern `clip` (SET, SELECT+R1); Seitenmenü bricht Zeilen um
- Projekte `projects/<Name>.gbx` (aktives in settings.cfg `project`), Presets `presets/<ENGINE>/<Name>.gbp`

## Groovebox-OS (`os/`)
- Eigenes Image statt ArkOS: Linux `LINUX_VERSION` (gregkh/linux-Tag) + ROCKNIX-Patches/DTS (gepinnt `ROCKNIX_COMMIT`, `os/versions.env`), Panel aus ArkOS-DTB als Overlay `os/dts/panel-arkos.dtso` (generic-dsi), eigener Tree `rk3326-groovebox-r36s.dts` (OTG-Port an, usb-role-switch)
- `os/kernel/build.sh` (arm64-Runner nativ), `os/uboot/build.sh` (x86: rkbin-Tools), `os/rootfs/build.sh` (mmdebstrap Debian trixie, Overlay in `os/rootfs/overlay`), `os/image/build.sh` (MBR: U-Boot @64, GBBOOT FAT, GBROOT ext4; GROOVEBOX FAT wird beim 1. Start angelegt)
- Power-Taste (evdev `rk805 pwrkey`, logind ignoriert sie): kurz `screenOff` + bl_power, lang `powerOff()` (speichern, `systemctl poweroff`); ruhiger Start (`quiet loglevel=3 panic=10`, Diagnose per extlinux.conf), Hostname `synth-city`, Kernel `-synthcity`
- Kein Initramfs: Root per `root=PARTUUID=47425653-02` (feste MBR-ID in image/build.sh), `LABEL=` geht nur im Userspace; ROCKNIX-Config hat `PANIC_TIMEOUT=1` (Panic = sofortiger Neustart) → Testphase mit `panic=60 console=tty0`
- Bild auf dem OS: `src/drmout.cpp` (make DRM=1, `GB_DISPLAY=drm`): SDL-Software-Renderer auf Surface → DRM-Dumb-Buffer (Standard: 1 Puffer direkt beschrieben, Page-Flip war langsam/springend; `GB_DRM_FLIP=1` testet Flip), SDL läuft mit Videotreiber offscreen; GPU-Weg (SDL kmsdrm/Panfrost) blieb schwarz. Umschalten per `/data/config/groovebox.env`; `present()` statt `SDL_RenderPresent`. Panel liest den RGB-Strom versetzt (Bild ~92 px verschoben + Farben rotiert) → Ausgleich `drmOutSetByteOffset` (settings.cfg `display_offset`, Standard 277 = 3·92+1, SET „Bild-Versatz“, schnelle Pixel-Variante N=off/3, r=off%3); im DRM-Modus zeichnen `fill/text/drawLine/clearScreen` direkt in `fbPix` (10x schneller als SDL-Software-Renderer, Benchmark `GB_BENCH=200 [GB_FB=1] ./groovebox --shot x.bmp 0`); eigentliche Ursache vermutlich DSI-Timing im Panel-Overlay
- App-Update ohne Image: `tools/os-update.sh` → `dist/groovebox-os-update.tgz` (groovebox DRM=1, pc-modus.sh, sbin/, VERSION; Build-Job `os-app` in build.yml, Asset im Release nightly); Wege: PUT `/api/update` (web.cpp, nur wenn /etc/groovebox-os), `/data/update/*.tgz`, deploy.ps1/.sh (erkennt `"os":true` in /api/list); `groovebox-run` installiert vor dem Start, Rollback nach 3 Fehlstarts <15 s
- Workflow `.github/workflows/os.yml` → Release **os-nightly**, läuft nur bei Änderungen unter `os/` (Nutzerwunsch: OS nicht unnötig neu bauen, App kommt per App-Update); Kernel/fremder Code nicht im Container bauen, nur in CI
- Gerät: `/opt/groovebox` (Symlinks nach `/data` = Partition GROOVEBOX), Dienst `groovebox.service`, Logs: App `/var/log/groovebox/groovebox.log` (Rootfs, sonst blockiert offenes Log das Aushängen von /data für den Laufwerk-Modus; Kopie nach /data/logs beim Beenden, enthält alle 10 s „Bild: fps…“), `/data/logs/{boot.txt,update.log}`, im Web unter „Logs“ (`/api/log?name=`); groovebox-run setzt CPU/devfreq-Governor performance, `pc-modus.sh` (aus|an|an audio|laufwerk|laufwerk-aus, configfs-Gadget RNDIS+MIDI+UAC2 bzw. Mass-Storage), SET „USB-Laufwerk“ (`startDrive/stopDrive`, nur wenn `/etc/groovebox-os` existiert); USB-Audio zum PC nie als Takt-Ausgang (Gadget blockiert, wenn der PC nicht aufnimmt → Sequencer stand): `src/usbaudio.cpp` Ringpuffer + Thread, nicht-blockierend, aus `audioCb` gefüttert, SET „Audio an PC (USB)“ (`usb_audio`), Gadget-Geräte aus der Ausgangsliste ausgeblendet. **Gelöst:** Windows bekam nur Stille, solange die isochronen Pakete jede 125 µs liefen (dwc2) → `p_hs_bint/c_hs_bint=4` (1 ms) + `req_number=4` in pc-modus.sh (überschreibbar `GB_UAC_BINT/GB_UAC_REQ`). Diagnose: SET „Testton an PC“, Log „USB-Audio: … Pegel“, Web-Log „usb-diagnose“. USB-Taktausgleich: Schreib-Thread liest Ring mit geregelter Rate (Ziel 1024 Frames, ±0,3 %, lineare Interpolation). PC→R36S: `pcInThread` liest Gadget-Capture, `pcInMix` im audioCb (nach usbAudioPush, kein Echo), Aufnahme `pcRec*` → `savePcRecording` samples/pc/pc-NN.wav, SET „PC-Ton über R36S“ (`pc_in`) / „PC-Ton als Sample aufnehmen“. Getrennte Lautstärken: `usbAudioSetGain(cfg.usbVol)` (SET „USB-Lautstärke“), intern stumm bei USB-Audio (`internal_on_usb`, `intMuted` → hwVolumeSet(0)). Lautstärketasten: evdev `gpio-keys-vol` → `hwVolumeSet` (Codec Master, settings `hw_volume`)

## Sprache und Datei-Dialoge
- Sprache: `g_lang` (main.cpp, settings `language`, SET „Sprache / Language“), `TR(de, en)` in params.h; Listen als `X_DE`/`X_EN` + `#define X (g_lang ? …)` (PAGE_LONG, GROUP_NAMES, MACHINE_LONG, SCALE_LONG, ARP_MODES, ARP_CHORDS, RHY_NAMES); lokale Listen ohne `static`; `paramhelp.h` mit en-Spalte; Log-Ausgaben (printf) bleiben deutsch. Neue Texte immer mit TR schreiben – Selbsttest `langCheck` zeichnet alles auf Englisch und meldet deutsche Reste (Umlaute/Wortliste)
- Datei-Dialoge `src/filedlg.inc`: Tastatur `openKeyboard(KB_SAVEAS|KB_NEW|KB_PSAVE)`, Explorer `openBrowser(FB_SAMPLE|FB_PROJECT|FB_PRESET)` (Samples hierarchisch aus der Bibliothek `libName` „ordner/unter/name“, `idx` = Bibliotheksindex, Wählen = `poolAssign`, Vorhören über `PREVIEW_SLOT`; Presets: Wurzel = Werksklänge + Engine-Ordner); Projekte per Name (`cfg.project`, settings `project`, alt `song N` → „songNN“), `projectPath/presetFile`, Rückfragen über `pendingName` + ACT_SAVEAS/NEWNAME/PSAVENAME/LOADNAME; Samples bis `SAMPLE_DEPTH` 8 Ebenen, Name 96 Zeichen (Web gleiches Limit)
- Samples (`src/samples.*`): **Bibliothek** = nur Namen aller WAVs (`libScan/libCount/libName/libFind`, `MAX_LIB` 8192, `libSkipped` = MP3/AIFF/FLAC …), **Pool** = Plätze 0..252 im RAM (`MAX_SAMPLES` 254, Platz 253 `PREVIEW_SLOT`), Spur-Parameter SMPL = Pool-Platz. main.cpp: `poolSetSlot/poolAssign` (Pool voll → unbenutzten Platz wiederverwenden), `poolUsed`, `poolLoadForProject`, `poolDefaults`. Projektdatei: nach `Project` Trailer „SPL1“ + u16 Anzahl + je (u8 Platz, u8 Länge, Name) (`writePoolTrailer/readPoolTrailer`); Presets (.gbp) gleicher Trailer mit 0/1 Eintrag. Alte Dateien ohne Trailer: Nummer = Position in `libLegacyList` (eine Unterordner-Ebene, sortiert mit „.wav“, nur lesbare WAVs, max. 128). Sample-Engines prüfen `smp->data` (Platz kann geleert werden). `samplesLoad(dir)` füllt den Pool alphabetisch (nur Tests/Bench/Screenshots). SET „Samples“ zeigt Bibliothek/Projekt/fehlend/andere Formate

## Tests
- `make test [SAN=1]` → `tests/unit.cpp` (Engine ohne UI); `./groovebox --selftest [sek]` und `--bench [datei]` aus `src/selftest.inc` (am Ende von main.cpp eingebunden; `selfTesting` blockiert USB/Lernmodus/Audio-Gerät; UI-Simulation `simFrame/tap/combo/flickL/stickR`, `goPage/goSlot` zählen Tasten → Bedienweg-Report); SET „Leistungstest“ → /data/logs/bench.txt; CI-Job `tests` mit Sanitizern, bench-arm64.txt im Release
- R36S-Messung (A35 1,3 GHz ≈ 14× langsamer als CI): Worst Case war 86 % → Optimierungen: `fastExp2/fastExpE` in update/ADSR/decayCo, `lfMask` statt LFO-Schleife in `P()`, Blockgröße 32 (`processBlock`-Arrays [32]), Delay/Reverb-Leerlauf (`dQuiet/rQuiet`), `sin01` ohne floorf, P()-Aufrufe aus der Sample-Schleife, Kick-Sweep/Klick nur solange hörbar, `-fno-math-errno`, `-mcpu=cortex-a35` auch im nativen arm64-Build (Makefile); UI: `fbMix` (gepackte Alpha-Mischung), Schrift-Schnellweg, Menü/Hilfe deckend, drmOutPresent ohne Abfragen pro Pixel, 30 fps in Ruhe. Messwerkzeug: callgrind-Instruktionen (Basis-Werte in docs/SPECS.md)
- Mehrkern-Audio: `Engine` startet in init einen Helfer-Thread (`wkMain`, nicht bei 1 CPU oder `GB_AUDIO_THREADS=1`); processBlock sammelt klingende Stimmen in `wkList`, ab Gewicht ≥ 8 holen sich beide Threads Stimmen per CAS (`wkClaim` = Block<<16|Index, `wkClaimOne`), Helfer rendert in `wL/wR/...`, Audio-Thread wartet nur auf `wkDone` laufender Helfer-Stimmen; Helfer spinnt kurz, sonst `sem_wait(wkGo)` + `wkSleeping`; Priorität vom Audio-Thread (audioCb setzt SCHED_FIFO 70); SET „Audio-Rechenkerne“ (`cfg.cores`, settings `audio_cores`, `eng.audioThreads`); Tests: `testMultiCore` (2 frische Engines, gleiches Ergebnis), `make test-tsan` (CI)
- Aussetzer: `saveProject` schrieb 1,5 MB unter der Audio-Sperre (Autosave alle 2 min) → jetzt Kopie `saveSnap` unter Sperre, Schreiben ohne Sperre via `.tmp` + fsync + rename; `mlockall` auf dem OS; Diagnose im audioCb (`audGapMax/audWorkMax/audLate`) → Log-Zeile „Audio: …“ alle 10 s, SET Info „Aussetzer N“
- Sample-Wiedergabe (SMPL/CHOP/GRAN): `smpRead` 4-Punkt-Hermite statt linear (Spiegelfrequenzen beim Transponieren/48 kHz: −62 dB → −76…−96 dB, ~15 % mehr CPU der Sample-Engines)
- Gefunden/behoben: Denormals (Kick 3,5× schneller, `flushDenormals()` in Engine::render), editValue/knobInfo auf globalen Seiten ohne Speicherseite (Index −8)

## Bauen
- Desktop: `make` (libsdl2-dev, libasound2-dev). Tests ohne Display: `./groovebox --render out.wav 4`, `./groovebox --shot bild.bmp <PG-Nummer | 20 Hilfe, 21 Lock, 22 Overlay, 23 Engine, 24 Skala, 25 Menü, 26 Abfrage>`

## Gerät (R36S) – per USB-Kabel
- Auf dem Synth City → Seite SYS → **USB = PC** (OTG-Port freigeschaltet via „Groovebox - OTG-Port freischalten“, geladene DTB: `rk3326-r35s-linux.dtb`)
- R36S: `192.168.77.1`, PC bekommt `192.168.77.10`. SSH: `ark` / `ark`
- Aufspielen: `tools/deploy.ps1` (Windows) bzw. `tools/deploy.sh`; Log: `deploy.ps1 -Log`; Pfad auf dem Gerät `/roms/ports/groovebox/`
- Kernel hat nur Netzwerk-Gadgets (ecm/rndis/ncm) – MIDI zum PC über RTP-MIDI (rtpMIDI unter Windows)
- Bekannt: dwc2 hängt beim Rollenwechsel ohne Neuladen des Moduls (pc-modus.sh lädt dwc2 neu)
